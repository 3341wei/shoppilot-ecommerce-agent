# ShopPilot 功能清单

> **说明：本文是最初的完整版功能规划（76 项），不是当前实现清单。**
> 当前「速通版」已实现的范围与验收剧本见 [README](../README.md)；
> 本清单保留作为后续迭代的 backlog。
>
> 优先级定义：
> **P0** = 演示闭环必须（不做就不成立）；**P1** = 完整体验与运营能力；**P2** = 加分项/进阶。
> 状态列在开发启动后维护：`未开始 / 进行中 / 完成 / 暂缓`。

## 2. A. 会话与 Agent 核心

| 编号 | 功能 | 优先级 | 说明 | 验收标准 |
|---|---|---|---|---|
| F-A01 | 按角色构建 Agent | P0 | `buyer` / `operator` 两套工具与提示词 | 买家请求中不出现运营工具；运营可查指标 |
| F-A02 | 多轮会话记忆 | P0 | `thread_id = user_id:session_id` | 同一会话追问“那第二款呢”能理解上下文；不同会话互不影响 |
| F-A03 | SSE 流式回答 | P0 | token 逐字推送 | 首 token 可感知；可中途停止；`done` 后答案完整 |
| F-A04 | 工具调用轨迹 | P0 | `tool` / `tool_result` 事件 | 前端能看到调用了哪些工具及顺序 |
| F-A05 | 来源 artifact 传递 | P0 | 工具返回结构化来源 | 回答附来源；并发请求来源不串 |
| F-A06 | 会话清理 | P0 | DELETE session | 清理后追问不记得上文 |
| F-A07 | 工具调用上限 | P0 | 单轮 ≤ 6 次 | 构造循环问题能终止并给出兜底话术 |
| F-A08 | 上下文裁剪 | P1 | 工具结果截断 + 最近 10 轮 | 长会话不因上下文超限报错 |
| F-A09 | 会话摘要 | P2 | 超长会话做滚动摘要 | 20 轮后仍能记住关键约束（预算/订单号） |
| F-A10 | 非流式接口 | P1 | `/api/agent` | 与流式结果一致 |
| F-A11 | 子 Agent 拆分 | P2 | 域过多时按域路由 | 工具 > 25 个时选择准确率不下降 |
| F-A12 | 外部 checkpointer | P2 | Redis/Postgres | 支持多 worker 水平扩展 |

## 6. E. 运营分析

| 编号 | 功能 | 优先级 | 说明 | 验收标准 |
|---|---|---|---|---|
| F-E01 | 销售总览 | P1 | GMV、订单数、客单价、退款率 | 指标口径与时间范围随结果输出 |
| F-E02 | 类目/商品下钻 | P1 | 按 GMV/退款率排序 | 能回答“哪个类目拖后腿” |
| F-E03 | 库存预警 | P1 | 断货/紧张/紧急 + 滞销 | 阈值可配置；给出补货数量建议 |
| F-E04 | 评价归因 | P1 | 差评主题聚类（规则/关键词） | 输出 Top 主题与代表评论 |
| F-E05 | 营销文案 | P1 | 按渠道（小红书/详情页/短信） | 不虚构功效，不使用绝对化用语 |
| F-E06 | 趋势对比 | P2 | 环比/同比 | 明确对比基期，缺数据时说明 |

## 8. G. 工程 / 安全 / 部署

| 编号 | 功能 | 优先级 | 说明 | 验收标准 |
|---|---|---|---|---|
| F-G01 | 配置中心 | P0 | pydantic-settings + 启动校验 | production 缺 Key 拒绝启动；development 相关接口 503 |
| F-G02 | API Key 鉴权 | P0 | 常量时间比较、多 Key 轮换 | 缺失/错误返回 401，不泄露期望值 |
| F-G03 | 限流 | P0 | 滑动窗口，普通/ ingest 分开 | 超限返回 429 + `Retry-After` |
| F-G04 | 安全响应头 | P0 | CSP、X-Content-Type-Options 等 | 响应头齐全；前端无内联脚本违规 |
| F-G05 | 统一错误体 | P0 | code/message/request_id | 不返回堆栈与内部路径 |
| F-G06 | 请求体限制 | P0 | 64KB | 超大请求 413 |
| F-G07 | 结构化日志 | P0 | text/json，request_id 贯穿 | 日志可 grep 到单次请求全链路 |
| F-G08 | 健康探针 | P0 | `/healthz`、`/readyz` | readyz 检查 DB、索引、密钥配置 |
| F-G09 | PII 脱敏 | P0 | 手机/地址/姓名 | 接口与日志均无明文；LLM 输入已脱敏 |
| F-G10 | 审计日志 | P0 | 写操作留痕 | 每次 confirm 有记录，含 request_id |
| F-G11 | 幂等 | P0 | token 单次 + 工单唯一约束 | 并发重复 confirm 只产生一张工单 |
| F-G12 | 索引原子重建 | P1 | 新 collection + ACTIVE 指针 | 重建期间查询不中断；失败保留旧索引 |
| F-G13 | Docker Compose | P1 | 非 root、健康检查、卷持久化 | 一条命令启动；重启数据不丢 |
| F-G14 | CI | P1 | ruff + pytest + 密钥扫描 | PR 必须通过 |
| F-G15 | 密钥扫描 | P1 | 提交前/CI | 示例密钥不误报，真实形态能拦截 |
| F-G16 | 生产身份方案 | P2 | JWT/OAuth 替换演示头 | 角色来自签名令牌，客户端不可伪造 |
| F-G17 | 指标监控 | P2 | Prometheus / OpenTelemetry | 有工具错误率、LLM 延迟面板 |

## 11. 明确不做（Out of Scope）

| 不做 | 原因 |
|---|---|
| 真实支付、真实下单 | 涉及资金与合规，演示用订单数据即可 |
| 自动退款 / 自动改价 | 高风险写操作，只生成工单或建议，不直接执行 |
| 真实平台 OpenAPI 对接 | 需要商家资质与密钥；预留 adapter 接口 |
| Text-to-SQL / 任意查询 | 注入风险 + 口径不可控，只用白名单指标函数 |
| 推荐模型训练 | 用规则 + 向量相似度足够展示能力 |
| 多模态（图片搜同款/语音） | 与核心闭环无关，P2 以后再说 |
| 完整 RBAC 后台 | 只做演示角色；生产身份方案列在 P2 |
| 多租户 SaaS | 超出作品集范围 |

## 12. 非功能需求

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 首 token 延迟 | < 2.5s（不含冷启动） | 前端埋点 / 日志 |
| 非 LLM 接口 P95 | < 300ms（本地数据） | 压测脚本 |
| 工具单次执行 | < 1s（检索含 rerank < 2s） | 日志 latency_ms |
| 单轮工具调用 | ≤ 6 次 | 代码硬限制 |
| 测试耗时 | 全量 < 30s | pytest |
| 核心规则覆盖率 | ≥ 85% | coverage |
| 意图→工具准确率 | ≥ 85% | `eval_agent.py` |
| 商品检索 recall@3 | ≥ 80% | `eval_retrieval.py` |
| 并发 | 20 并发会话不串数据 | 并发测试 |
| 可访问性 | 键盘可操作、对比度 ≥ 4.5:1 | 人工检查 + axe |
